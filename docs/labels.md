# ラベルの運用ルール

- 状態：試行（2026-11-05 導入）。変更は Issue で提案し、プロジェクトオーナー（主催者さん）の承認で決める
- 共通：同じ内容のルールを、MuneakiKanda の AI 関連リポジトリで共通に使う。各リポジトリ固有の補足は最後の節に書く

## 1. 目的

**誰の番かを、一目で分かるようにする。**

主催者さんが `待ち:主催者` で絞り込めば、判断・確認・取り次ぎが必要なものがすべて見える状態にする。このラベルを、主催者さんの判断を待つものの**唯一の一覧**とする。チャット、手紙、引き継ぎ書などに、別の一覧を作らない。一覧を二つ持つと、必ずずれるため。

## 2. ラベル

| ラベル | 色 | 意味 |
| --- | --- | --- |
| `待ち:主催者` | `#d93f0b` | 主催者さんの判断・確認・取り次ぎ待ち |
| `待ち:ジェミ先生` | `#5319e7` | ジェミ先生の回答・作業待ち |
| `待ち:きみっち` | `#0e8a16` | きみっちの回答・作業待ち |

- 名前・色・説明は、すべてのリポジトリで同じにする。
- ほかの人を待つ必要が出てきたら `待ち:<名前>` を追加する。追加するときは、ほかのリポジトリにも同じラベルを作り、この表を更新する。

## 3. 付け方・外し方

1. **付ける人**：判断や作業を相手に渡した人が付ける。
2. **付けるときは、何を待っているかをコメントに書く。** 主催者さん宛てでは、スレッド全体を読まなくても答えられるように、決めてほしいことと選択肢を書く。複数あるときはチェックボックスにまとめる。
3. **外す人**：待たれていた人が答えたら、答えた人か、次に状態を変える人が外す。次に別の人を待つなら付け替える。状態を変えた人が、ラベルも付け替える。
4. 一つの Issue・PR に、複数の待ちラベルを同時に付けてよい。
5. 閉じた Issue・PR からは外す。

## 4. ラベルが意味しないこと

- **ラベルは承認ではない。** ラベルが外れたことも、承認を意味しない。承認や決定は、主催者さんのコメントかマージで記録する。
- ラベルが付いていない Issue・PR は、誰も待っていないとは限らない。付け忘れに気づいたら、気づいた人が付ける。

## 5. 公開リポジトリでの注意

待っている内容を書くときも、個人的な会話や手紙の引用、第三者の情報、秘密情報（API キー、パスワードなど）は書かない。

## 6. このリポジトリでの補足

- このルールは、レビュー運用規約 v2 の候補（Issue #4）で 2026-11-04 から試行している待ちラベルを、文書にまとめたもの。規約 v2 の採否とは独立に、このファイルの変更で運用を改める。
- PR のマージ可否は、ラベルではなく [レビュー運用規約](review-guidelines.md) の判定で伝える。
- 状況ボード（固定 Issue）を作るかどうかは、ラベルの試行の結果を見て判断する（Issue #4）。
